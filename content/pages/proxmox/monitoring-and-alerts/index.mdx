# Monitoring And Alerts

Healthy homelabs do not stay healthy because their owners are lucky.

They stay healthy because the host is being watched, the important services emit signals, and failures have a way to leave the machine before they turn into a Saturday rebuild.

This subsection keeps those two layers separate on purpose.

- the lightweight manual checks that sharpen your intuition
- the proper Prometheus and Grafana stack for when the lab is mature enough to justify one

Where that stack runs matters as much as what it runs. Mine started in a container on the host it was watching. It now runs on [a board of its own](/pages/proxmox/monitoring-and-alerts/monitoring-on-its-own-board), so it is still there when a host is not.

## Start With The Simple Checks

Before building a dashboard, know the host well enough to inspect it directly.

```bash
# SSH into Proxmox
ssh root@10.0.10.21

# Proxmox version and package versions
pveversion -v

# View system load and memory
top -b -n 1 | head -20

# Check disk usage
df -h /
zpool list
zfs list

# Monitor GPU
nvidia-smi

# Check for errors in logs
tail -50 /var/log/syslog | grep -i error
dmesg | tail -20
```

That does not replace a monitoring system, but it does teach you what normal looks like before a graph starts telling you stories.

## The Stack Shape

The stack I run now uses:

- the node exporter on every Debian host, both Proxmox nodes included
- two exporters for the GPUs and the model server, inside the container that runs the models
- the blackbox exporter, probing the HTTPS routes, DNS and the internet
- Prometheus for scraping, storage and the alert rules
- Alertmanager, sending the alerts to my phone through ntfy
- Grafana, as a viewer only

## How To Read It

If the host is new or the lab is still small, start with the manual checks above and wait until patterns emerge.

When the lab runs things you care about, read [Monitoring On Its Own Board](/pages/proxmox/monitoring-and-alerts/monitoring-on-its-own-board). The two older pages are still a working way to get a first stack up on a single host.
