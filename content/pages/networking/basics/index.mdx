# Networking Basics

These concepts sit underneath everything else in a homelab. Routers, containers, VMs, DNS, and service discovery all rely on the same core networking building blocks.

I teach them here with my own lab as the example, from the first idea (what a cable carries) to a stateful firewall and VLAN tags on a trunk. Every step in a diagram says which **layer** it happens at, and [OSI Model](/pages/networking/basics/osi-model) explains the tags.

The everyday picture runs through every page: a network is a **building** of flats. The **MAC address** is the label on a flat's door, the **IP address** is the street address, and the **port** is the person inside the flat.

## The Cast

These names appear in almost every diagram. The examples show the lab as it ran in November 2026.

| Name in diagrams | What it is | Address |
|---|---|---|
| **Mac** | My admin MacBook, on a USB 10G adapter, plugged into the router's `ether2` | `10.0.20.100` (VLAN 20) |
| **Router** | MikroTik RB5009: router, firewall, NAT, and a switch | `.1` in every VLAN, e.g. `10.0.20.1` |
| **Switch** | MikroTik CRS310: a switch only (no routing for my traffic) | `10.0.20.2` (its own management) |
| **Pi-hole** | The primary Pi-hole, a Raspberry Pi 3B on the router's `ether3` | `10.0.40.10` (VLAN 40) |
| **Proxy** | A Raspberry Pi 4B on the router's `ether5`: Squid and apt-cacher-ng | `10.0.40.19` (VLAN 40) |
| **ts-sbc** | A Tailscale subnet router, a Raspberry Pi 4B on the router's `ether4` | `10.0.20.13` (VLAN 20) |
| **Rock Pi** | A Rock Pi 5B that runs monitoring, on the switch's `ether2` | `10.0.50.10` (VLAN 50) |
| **pve-epyc / pve-ryzen** | The two Proxmox nodes | `10.0.10.20` / `10.0.10.21` (VLAN 10) |
| **Caddy** | The reverse proxy, a container on pve-ryzen | `10.0.20.12` (VLAN 20) |

MAC addresses are never written down. Diagrams use names instead: `mac:Mac` means "the admin Mac's MAC address", `mac:Router` means "the router's MAC address on that VLAN", and so on.

## Suggested Reading Order

Read the pages in the order above. Each one only uses words from the pages before it.

If you are troubleshooting a service that is already deployed, start with the last section of [OSI Model](/pages/networking/basics/osi-model): it shows how to find the broken layer. After that, the router, addressing, and DNS pages are usually the fastest path.
