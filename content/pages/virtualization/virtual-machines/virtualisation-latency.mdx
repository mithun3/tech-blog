# The Virtualisation Tax in Microseconds

Everyone talks about virtualisation overhead. Few people measure it.

The argument usually goes like this: "Bare metal is faster." Yes. But *how much* faster? Are we talking milliseconds or microseconds? And does tuning the hypervisor actually close the gap, or just move the bottleneck?

To stop guessing, I ran the numbers. 

Here is the exact cost of the hypervisor tax, measured in microseconds, across three identical Rocky Linux environments:

1. **Bare Metal**: Rocky Linux running directly on the hardware.
2. **Untuned VM**: Proxmox VM with default settings (emulated devices, generic CPU type, no pinning).
3. **Tuned VM**: Proxmox VM built for latency (VirtIO SCSI Single, CPU pinning, host CPU type, NUMA alignment).

Here are the facts.

## So, Who Actually Cares?

Look at the numbers above. The difference between bare metal and a tuned VM is measured in **microseconds**. 

If you are running:
* A web server
* A standard database
* A media server
* A CI/CD runner

You do not care about 50 microseconds. You care about the ability to snapshot the machine before an upgrade. You virtualise.

You only care about this tax if you are running:
* High-frequency trading algorithms.
* DPDK/kernel-bypass networking at 100Gbps.
* Hard real-time industrial systems.

For everyone else, the tax is real, but the cost of paying it is lower than the cost of managing bare metal without it.
